Algorithms – Big-O Complexity Analysis

Complexity analysis provides a mathematical framework for measuring how an algorithm's resource usage (time or memory) grows as the input size n increases. Rather than measuring actual runtime in seconds — which depends on hardware and implementation — we express growth rate using asymptotic notation.

Big-O notation O(f(n)) describes the upper bound on growth rate, capturing the worst-case scenario. Common complexity classes, from fastest to slowest growth: O(1) constant — accessing an array element by index; O(log n) logarithmic — binary search, balanced BST lookup; O(n) linear — single-pass traversal; O(n log n) linearithmic — merge sort, heap sort; O(n²) quadratic — bubble sort, insertion sort on unsorted data; O(2ⁿ) exponential — brute-force subset enumeration; O(n!) factorial — brute-force permutation generation.

Alongside Big-O, two complementary notations exist: Omega Ω(f(n)) gives the lower bound (best case), and Theta Θ(f(n)) gives a tight bound when upper and lower bounds coincide.

To analyze an algorithm, identify the dominant operation (the one executed most often), count how many times it runs as a function of n, and drop constant factors and lower-order terms. For example, a nested loop where both indices run from 0 to n gives n² iterations — O(n²) — regardless of whether the inner body performs 1 or 100 constant-time operations.

Space complexity applies the same framework to memory usage. Recursive algorithms often have O(depth) space due to call stack frames. Understanding complexity is essential for selecting appropriate data structures and algorithms for real-world performance constraints.
